# Milestone 1: engine, content and simulator

**Goal:** the battle rules run headless in a typed, deterministic engine (`src/engine/`) that reads its numbers from `src/content/`. A simulator then shows the engine plays like 3.x.

**Done when:** simulated win rates and end-of-level castle health, for every built level on each difficulty, match a baseline recorded from 3.x. "Match" means within the spread the old game shows between its own runs.

The live game (`src/main.js`) keeps running unchanged throughout. Nothing here is bundled until milestone 2 wires the renderer to the engine.

## Rules for this milestone

- **The engine is pure.** No DOM, Three.js, clock or `Math.random`: randomness comes from `src/engine/rng.ts`, carried in the state.
- **No retyped numbers.** Numbers come from `src/content/`, which `npm run extract` copies from `main.js`. `test/content.test.ts` fails if the two drift. Until 3.5 ships, balance changes go in `main.js` first, then you run `npm run extract`.
- **Port first, improve later.** Port behaviour as it is, including quirks. Note any bug found along the way here; fix it in `main.js` and the engine together.
- **Tests:** every ported system gets a Vitest file in `test/` that fails when its rule breaks.

## Steps

- [x] **Tooling:** TypeScript, Vitest and tsx; the `test`, `typecheck` and `extract` scripts.
- [x] **Content:** maps, enemies, towers, barracks and drum, spells, campaign, skill tree and AI weights, extracted with a parity test. `RANKX` (tooltip text) stays with the UI.
- [x] **Rng and waves:** seeded mulberry32; `hpMul`, `waveCounts` and `waveGroups`.
- [x] **Map geometry** (`src/engine/map.ts`): tile grid, paths, `pathAt` and `smoothPath`, AI samples, build plots and the castle centre.
    - Plot placement uses the fixed `fbm` noise, not `Math.random`, so it was already deterministic.
    - `test/map.test.ts` matches all 7 maps bit for bit against the 3.x game: plots, path lengths, samples and tiles.
    - The gate and the flag are only drawn, so they stay with the renderer.
- [x] **Enemies** (`src/engine/enemies.ts`, game state in `src/engine/state.ts`): spawning, walking the road with the spread across it, the bog, slows, freezes, stuns and burns, armour and magic resist, kills and rewards, the castle hit and Last Stand. Specials: Shaman heals, Sapper charges, the Boar Rider's shrug, Gruk's roar and slow resistance, and flyers. Tested in `test/enemies.test.ts`.
    - Centre heights come from the 3D models, recorded with `window.__enemyDims()` into `src/content/enemy-dims.ts`. Ranges measured centre to centre in 3D (Shaman heal, Static Charge, Shatter, Wildfire) depend on them.
    - Melee is a placeholder (`src/engine/combat.ts`) until the Barracks step ports `enemyCombat`; the Boar Rider's charge into a soldier lives there.
    - The mark countdown, Bleed and Frost Bite tick in a War Council block in 3.x, so they move with that step.
- [x] **Towers** (`src/engine/towers.ts`, `src/engine/projectiles.ts`):
    - stats by level, specialisation and rank, with the War Council's stat picks; costs and sell refunds; the unlock gate; building, upgrading, specialising and selling, with plot blocking;
    - targeting modes and the mortar's dead zone;
    - firing for all five attacking towers and their War Council abilities;
    - arrows, cannonballs and bomblets, frost shards, Tesla chains and Overload, flame cones, fire and ice patches.
    - `test/towers.test.ts` matches every stat, cost and sell rate in 3.x exactly (`window.__towerStats`), with no picks and with every stat pick. Behaviour tests cover the rest.
    - **Approximation:** projectiles start straight above the tower, at the muzzle height recorded with `window.__muzzles()`. In 3.x they start at the turning head's muzzle, up to about .3 to one side. That changes an arrow's flight by about .02 s; the simulator will show whether it matters.
- [ ] **Barracks:**
    - [ ] soldiers, blocking up to 2 enemies, the fan-out (with the 3.1 fix), regen and respawn;
    - [ ] Rangers and Overwatch;
    - [ ] enemy attacks on soldiers (`ATK`).
- [ ] **War Drum:** haste aura, War Horn range, Hex Totem damage taken, and the drum skill-tree effects.
- [ ] **Spells:** Militia Call, Catapult Barrage, Frost Nova; cooldowns and the first-wave lock.
- [ ] **Economy and rules:**
    - [ ] starting gold, kill rewards, the early-call bonus;
    - [ ] difficulty multipliers;
    - [ ] the War Council effects (`SK_STAT`, `skH` checks, and the per-tick block: Arrow Slits, the mark countdown, Bleed, Frost Bite);
    - [ ] win, loss and stars.
- [ ] **Game loop:** `tick(state, inputs) → events` at a fixed 30 Hz, where inputs are build, upgrade, specialise, sell, aim, rally, call wave, cast and speed.
- [ ] **AI player:** port Watch mode's bot (`WANT` weights) as the simulator's player.
- [ ] **Baseline from 3.x:** run the old game's AI headlessly through its test hooks (`__probe`) for each built level on each difficulty, at least 30 runs each. Record the win rate and the castle-health distribution in `test/baseline.json`.
- [ ] **Simulator:** `npm run sim` plays the same matrix on the engine and compares it with the baseline.

## Found while porting

- **Dead tower abilities in 3.x:** `pierce`, `flak`, `pin`, `delay` (charges), `shrap` (shrapnel), `resid` and `debt` are read when a tower fires, but nothing ever switches them on. The engine leaves them out. Delete them from `main.js` when the renderer moves over, or give them War Council picks.
- **Shard `brittle`** (doubles damage on slowed enemies via `o.brittle = 3`) is never set to true in 3.x either.

- The soldier fan-out spin (fixed in 3.1, commit `58a9d90`): port the fixed version.
